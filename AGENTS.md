# Renaiss Deck Build — Deck Construction Simulator

One Piece TCG deck construction simulator: search cards, track a collection, build/export decks, see live prices, and simulate a Shop OS checkout for missing cards.

## Architecture

- **Next.js 16 App Router + TypeScript + Tailwind v4.** All pages are client components fetching internal API routes. There is **no `/card/[id]` page** — card detail always opens in `CardModal` (wrapping `CardDetailView compact`) from every surface (search tiles, collection, deck builder, analytics rows, meta-deck lists).
- **Card data & images:** OPTCG API (`https://optcgapi.com/api`, free community DB, no auth; images self-hosted on optcgapi). `src/lib/optcg.ts` syncs the full catalog (allSetCards + allSTCards + allPromos, ~4.7k printings, 3 requests) into the `op_cards` table once every 24h (kv key `optcg-synced-at`); search, pagination and lookups are then fully local. Card ids are optcgapi `card_image_id`s — base printing id == card code (`OP16-056`), variants suffixed (`OP16-056_p1`). Promo rows reuse base ids and are inserted with DO NOTHING so they never overwrite canonical set/starter-deck rows. Set search matches normalized `set_id` preferring the dashed official form (`ST-01` over promo group `ST01`), falling back to card-code prefix.
- **Prices:** Renaiss OS Index (`https://api.renaissos.com`, partner keys `X-Api-Key`/`X-Api-Secret` in `.env.local`, 10k req/day). `src/lib/renaiss.ts` looks codes up on demand via `/v1/search?q=<code>` (English RAW tiers only, best condition Raw A→D, variation print number matched to printing suffix) and caches per-printing rows in `renaiss_prices` + a per-code negative cache in `renaiss_fetches` (24h TTL, 4-wide global limiter, ≤24 uncached codes fetched per request — big set searches fill in over a few loads). `overlayRenaissPrices()` is called from every optcg.ts read path, so all routes get Renaiss prices with `priceSource`/`pricing.source` = `"renaiss"`; cards Renaiss doesn't cover fall back to optcgapi's scraped TCGPlayer price (`"tcgplayer"`). Raw-SQL price reads (`/api/decks` totals, `/api/analytics`) COALESCE `renaiss_prices.price_usd` over `op_cards.price_usd`. Both prices are kept side by side: `pricing.usd`/`priceUsd` = effective (Renaiss preferred, drives totals), `pricing.tcgUsd`/`priceTcgUsd` = TCGPlayer market always. `/api/cards/[id]/renaiss` serves the rich index detail (deltas, confidence, grade ladder, 30d FMV series for the chart) via the cached href, kv-cached 24h (`renaiss-detail:<r|g>:<href>`), stale on failure; CardDetailView renders it as an index-style hero panel with TCGPlayer boxes below. Printings with no raw-English tier get a **display-only** best-tier match in `renaiss_graded` (English any-company, ranked Raw A→D then grade desc/PSA first), shown on the card page labelled graded — never fed into effective prices/totals. Matching is by set-grouping word overlap (Renaiss files promo versions like "Dodgers One Piece Night" under own groupings): `_pN` printings need variation-number agreement + set/card-family overlap; `_prN` promo printings match only via their parenthesized promo label vs the grouping name, and never take variation-number matches (they'd steal the base print's price). Attribution ("Renaiss OS Index") is required when showing prices — footer + card detail label.
- **Local persistence:** better-sqlite3 → `data.db` at repo root (gitignored). Schema created on first use in `src/lib/db.ts`: collection, favorites, decks, deck_cards, card_stats (searches/views/favorites/owners/watch votes), search_log.
- **Single-user, no auth.** Stats counters are honest local counts, not seeded community data.
- **Meta decks (homepage):** `src/lib/limitless.ts` aggregates the last ~15 One Piece tournaments from the public Limitless API (`play.limitlesstcg.com/api`, no auth) into archetype stats + a representative decklist (best-placed list per archetype), cached 6h in `kv_cache` (key `op-meta`, stale served on failure). Decklist codes (`OP16-022`) resolve locally via `getOnePieceCardByCode` (base-printing preference); `cost`/`counterValue` on `CardDetail` come straight from the `op_cards` row (cost guarded to digits-only — a bad upstream row can put text like "Former Roger Pirates" in that column). Routes: `/api/meta` (grid), `/api/meta/deck?leader=` (modal: enriched cards incl. cost/counterValue, total, SIM text), `/api/meta/import` (POST from the "Open in Deck Builder" button *and* GET — the GET variant is what the deck-poster QR code encodes: scanning it imports the deck and redirects straight into `/decks/[id]`). UI in `src/components/MetaDecks.tsx`.
- **Deck poster export:** `src/lib/deckImage.ts` (`renderDeckPoster`, browser-only/canvas) draws the Meta Decks modal's lower half — banner (leader art + title + QR) → card grid (cost/quantity badges) → cost/type/counter distribution bars (each group scaled to its own max, not a shared one, or the biggest group crushes the rest) — as a single PNG data URL, downloadable via the modal's "Save Image" button. Card art loads through `/api/image-proxy` (host-allowlisted) since optcgapi.com and the official Bandai site send no CORS headers, and drawing a tainted cross-origin image blocks `canvas.toDataURL()`. Two-tier art fallback per card: our synced `op_cards.image` first, then `officialCardImageUrl()` (`en.onepiece-cardgame.com/images/cardlist/card/<code>.png`, same id/suffix convention as ours — reliably covers sets optcgapi hasn't synced yet, e.g. ST32/ST33) — only if both miss does the grid cell fall back to a "Not yet in catalog" placeholder.
- **Shop OS checkout is simulated** (`api/decks/[id]/checkout`): missing cards = deck qty − collection qty, allocated deterministically to fake shops by card-id hash, with merged-shipping pricing.

## Gotchas

- `serverExternalPackages: ["better-sqlite3"]` is required in `next.config.ts`.
- Route params are `Promise` in Next 16 (`await params` in routes, `use(params)` in client pages).
- HTTP headers are Latin-1: deck names may be non-ASCII, so export filenames use an ASCII fallback + RFC 5987 `filename*` (see `api/decks/[id]/export`).
- Card `image` / `imageLarge` are full optcgapi media URLs, usable as-is.
- Search order: card-code queries (`OP16-001`) → all printings of that code; set-code queries (`ST01`, `OP16`) → whole set via set_id (includes reprints with foreign codes); otherwise local name LIKE search. All searches return the full result set in one response — no pagination (card images are lazy-loaded).
- First request after the 24h sync TTL takes a few seconds (catalog re-download); optcgapi is a single-maintainer VPS — keep request volume low (the daily sync is the only external traffic).
- `APITCG_API_KEY` in `.env.local` is a leftover from the previous apitcg source and is no longer used.
